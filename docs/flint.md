# Flint 40B-A2.5B — bring-up notes

[RecursiveSI/flint](https://huggingface.co/RecursiveSI/flint), the agentic-coding MoE the user asked for on 2026-10-22, shipped on 2026-10-22 as [`mattbucci/Flint-AWQ`](https://huggingface.co/mattbucci/Flint-AWQ) (`launch.sh flint`) and closed its full-300 SWE-bench Lite cells on 2026-10-30. The README carries the live numbers (perf / VRAM / bake-off tables) and the open follow-ups; this file is the bring-up record — checkpoint, calibrator, serving config, the three defects found on the way (runaway repetition on the data-free build, the Marlin MoE group-32 kernel bug, the strict tool grammar's key order) and the needle-haystack finding. Receipts live under [`benchmarks/quality/flint/`](../benchmarks/quality/flint/) and [`benchmarks/flint/`](../benchmarks/flint/).

**Flint ([RecursiveSI/flint](https://huggingface.co/RecursiveSI/flint), 40B-A2.5B agentic-coding MoE — user request 2026-10-22) — SHIPPED on a calibrated INT4: `launch.sh flint` + [`mattbucci/Flint-AWQ`](https://huggingface.co/mattbucci/Flint-AWQ). The serving image is rebuilt on it and the 2-instance docker rollout smoke that produced 0/2 patches on the data-free build (runaway-repetition turns) now produces **2/2** (same instances, ~50 tool calls each, no `length` turn, 403 s / 352 s; [receipt](../benchmarks/quality/flint/docker-serving-smoke-2026-10-22.json)). Full-300 cells on the isolated harness (2026-10-30): opencode **182/300 (60.7 %)**, `omp` **186/300 (62.0 %)** — a McNemar tie (p = 0.57, 12 / 16 discordant; walls 9 / 3, empties 4 / 5, 0 errors), and the omp cell is a floor (strict-ordered grammar, below).**

Architecture: 256 sigmoid-routed experts top-6 + an ungated shared expert, 35 sliding-window (513) + 14 full-attention **NoPE** layers, learned per-head attention sinks, QK-norm — stock Qwen3-MoE blocks otherwise; the vendor's `flint_sglang` plugin is ported to v0.5.22 under `plugins/flint_sglang/` (installed by `setup.sh`; port delta in its README).

**Checkpoint:** BF16 is 79.6 GB and the vendor's MLX INT4 export cannot be re-encoded as AWQ (free per-group bias), and transformers has no Flint modeling file (no llmcompressor path) — so [`quantize_flint_awq_calib.py`](../scripts/quantize/quantize_flint_awq_calib.py) quantizes the BF16 base from its own reference forward: AWQ scale search folded into the norms / router / `up_proj` rows + GPTQ error feedback on activation Grams from 139K in-domain tokens (code reasoning, raw code, an agentic session, SWE-bench statements), g64 asymmetric on the integer-zero grid, router / embeddings / `lm_head` / sinks / norms BF16 → 20.9 GiB in ~13 GPU-minutes; `check_awq_scales.py --base` clean ([log](../benchmarks/quality/flint/check_awq_scales-Flint-AWQ-INT4-g64-gptq-2026-10-22.log)). It replaced the first, data-free MSE-RTN build after that one looped in agentic turns: the poisoned 68K prefix of the parity smoke replayed **11/24** runaway on the ship config (worse at lower temperature; every serving knob null; byte-faithful [`replay_turns.py`](../scripts/eval/replay_turns.py)), and a serving-independent fp32 reference forward ([`flint_cpu_reference.py`](../scripts/eval/flint_cpu_reference.py)) traced it to the data-free INT4 of the always-active path — attention + the 0.3B shared expert — KL to the BF16 base 0.73, top-1 64 %. The calibrated build: **KL 0.33, top-1 76 %, 0/24 and 0/48 on the replays**, same bytes, same decode ([receipt](../benchmarks/quality/flint/runaway-repetition-replay-2026-10-22.md)). Two findings to carry: **GPTQ generalises only where the Gram is well estimated** — the always-active path sees every calibration token and gains 20–36 % held-out, but a routed expert sees 0.5–12K rows for a 2,048-dim Hessian and GPTQ at the standard 1 % damping fits the noise (expert `down_proj` came out *worse* than the clip; the mechanism behind "GPTQ under-calibrates rare experts"); shrinking each expert's Gram toward the layer-wide one and damping the thin `down_proj` Hessians hard restores the gain ([probe](../scripts/quantize/probe_flint_expert_gptq.py), calibrator default). And a layer-specific `--keep-bf16` must land layer-qualified in `modules_to_not_convert` — a stripped `mlp` matches every `mlp.experts` and the loader allocates BF16 experts (OOM at boot).

**Serving (TP=2 / 262144):** triton attention (the only Ampere backend with sinks + `SWAKVPool`), AWQ-Marlin fused MoE (runner must stay `auto`), bf16 KV (triton rejects E4M3 on sm_86; the pool is 588,614 full / 29,430 SWA tokens at ratio 0.05), the `flint` parser trio, `--enable-fp32-lm-head`, sampling from `generation_config` (T 1.0 / top-p 0.95 / top-k 20); **TP=2 validated against TP=1** ([receipt](../benchmarks/quality/flint/tp-check-2026-10-22.md); a boot needs `swa_layer_tokens ≥ chunked_prefill_size + 513` or prefill deadlocks).

**Decode: `--triton-attention-num-kv-splits 64` (CUDA default 8) — 35.9 → 89.5 tok/s @261,916 actual, 114.8 → 147.5 @32K, 59 → 116 @131K, 1K within 1 %** ([bracket 8/32/64/128](../benchmarks/flint/kv-splits-bracket-2026-10-22.md)): at M=1 / TP=2 Flint has 2 KV heads per rank, so the default put 16 CTAs on 82 SMs and the 14 full-attention layers walked 262K tokens in 8 serial chunks; the same flag now ships on all four Gemma 4 presets (also triton; 13–24 → 30–58 tok/s at depth, [bracket](../benchmarks/gemma4-kv-splits-2026-10-22.md)). Prefill stays ~1–2.4 K tok/s on triton (a 250K fill ≈ 4 min) — the open lever.

**Tool calls: `FLINT_STRICT_TOOLS=1` (preset default) — the plugin's grammar enforces every tool's argument schema.** Flint ignores JSON-schema `required` keys on its own: opencode's `bash` needs `description`, `read` takes `filePath`; the checkpoint wrote `path` and no description in 23/24 calls with the grammar off *and* with it on schema-free, 20/20 with the schema enforced ([receipt](../benchmarks/quality/flint/tool-schema-probe-2026-10-22.json)). The vendor's SWE-bench path is mini-swe-agent (bash in text), which never exercises this contract.

**Strict mode also forces the schema's key order (found 2026-10-28 on the omp lane):** XGrammar's object grammar is ordered, omp declares its `i` intent string before `command`, and Flint writes `command` first — the grammar forced `<arg_key>i</arg_key>` onto the wire and the model put the command there (7.4 % of 11.5K bash calls swapped, 47 % of sessions re-emitting the call inside the forced value, 2 of the lane's 3 empties; the opencode lane, `command` first, had 0 in 14.8K calls). Fixed on main 2026-10-30 (metadata keys move last, required-ness kept; CPU test `test_flint_tool_grammar_key_order.py`; serving image rebuilt at the qwen36 boundary, parity smoke 2/2 with decode within 1 % — [receipt](../benchmarks/quality/flint/docker-serving-smoke-2026-10-30.json)); the `flint:omp` cell ran under the old grammar and is labelled strict-ordered — an omp re-roll under the fixed grammar is the open follow-up ([receipt](../benchmarks/quality/flint/tool-grammar-key-order-2026-10-28.md)).

**Needle: probe Flint with a natural-text haystack.** The stock repeated-sentence filler is a repetition attractor on the 14 NoPE layers (6/6 at 1K/32K, @0.1 only at 131K, 0/3 at 250K — reproduces greedy and after `/flush_cache`, kernels reviewed clean); an Open-Platypus haystack retrieves at **131K and 243.5K actual, both depths, greedy**, and 2/3 at 243.5K under the model's own sampling. `needle_band_probe.py --haystack` / `--chars-per-token` / `--flush` + [`build_natural_haystack.py`](../scripts/eval/build_natural_haystack.py) ship for it; Flint quality receipts use the natural haystack, the filler cells are a known-bad input ([receipt](../benchmarks/quality/flint/needle-haystack-discriminator-2026-10-22.md)).

**Open levers after the cell** (tracked in the README's next steps): `fp8_e5m2` KV, `--mem-fraction-static` (the full pool is 2.2× the window), prefill speed on triton; the group-32 checkpoint now serves correctly — its token salad was a Marlin MoE kernel bug (zero points of every group but the first in a k-tile were stale when a tile spans several groups; patch 067, unit test `scripts/eval/test_marlin_moe_zp_groups.py`), fixed 2026-10-25 with no decode cost (g32 through the fixed kernel: 164.2 / 148.1 / 92.6 tok/s, tripwire PASS); a calibrated g32 build is now a real quality lever (data-free g32 already halves the g64 RTN KL).

## KV dtype: `fp8_e5m2` ships (2026-10-31)

The first experiment after the bake-off pause. Triton rejects E4M3 on sm_86 but compiles `fp8_e5m2`; with the 14
full-attention NoPE layers reading the whole KV every step, halving their bytes is the depth lever: **+12 % @261,916
actual (93.2 → 104.4 tok/s), +5 % @131K, −1 % @32K, −4 % @1K** (a fixed read-side dequant cost; crossover ≈ 64K), KV
pool 589K → 1.18M. Quality at parity with bf16 KV on the natural-haystack needle (131K 8/8 on both arms; 252K @0.9
hits and @0.1 / @0.5 miss on *both* — Flint's own cliff past ~250K, see below), HumanEval 29/40 vs 28/40, the 256K
tool probe identical row by row. Receipt: [`benchmarks/flint/kv-dtype-ab-2026-10-31.md`](../benchmarks/flint/kv-dtype-ab-2026-10-31.md).

**Retrieval is marginal from ≈240K actual at depths ≤ 0.5, reliable at depth 0.9 to the window — KV-dtype independent.** Natural haystack, greedy, flushed, ×2–3 per cell at 240.8K / 246.5K / 252.4K on both bf16 and e5m2 KV: depth 0.9 14/14 on each arm; depths 0.1 + 0.5 e5m2 2/14, bf16 1/12, the hits not aligned by arm (greedy knife-edges at identical prompts), the misses confident wrong answers (`C`, `B`, `hunter2`, `swordfish`, "I don't know"). 131K is 8/8 on both arms; where the zone starts between 131K and 240K is the open bracket (160K / 200K / 220K). R9700 reproduces the band the same day on their FP8 build (243.5K @0.1 miss, 248K @0.1 / @0.5 miss, @0.9 found; sink kernels verified against a torch reference) and finds the same text dependence in a 32K band — the checkpoint's behaviour across INT4 / FP8 and CUDA / ROCm, not a quantization or serving defect. Treat the last ~8 % of the 262,144 window as unreliable for mid-context retrieval. The stock filler of `probe_256k_tooluse.py` is the same repetition attractor as the filler needle (0.4, length-stops from 131K, both arms) — Flint needs a natural-haystack tool probe before its 256K tool-use row means anything.
